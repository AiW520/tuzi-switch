# ADR-021：统一供应商定向复用与实际配置同步

- 日期：2026-11-11
- 状态：用户选择方案 B；仅本地实现与验证
- 任务：UC-UNIVERSAL-01
- 基线：TA-AC-1.5-B4 / system-token-v1，不改账户接口

## 背景与选择

兔子助手已包含统一供应商的表单、原生命令、SQLite 存储和三工具配置转换，但独立侧栏页缺少添加按钮，旧添加弹窗仅保存父记录，同步只更新数据库。用户选择定向复用 CC Switch 的改进，而非整套替换供应商模块。

对照来源为 `/Users/sdy09/Documents/ChatGPT/cc switch`，本轮核查 HEAD `abf50589ed0ff60900ead3a83cfda9ff009cd6ef`。所引用会话最终同步的是 main，不是 dev。参考 `UniversalProviderPanel.tsx`、`AddProviderDialog.tsx` 和 `services/provider/mod.rs` 的新增后同步、保留子配置元数据及当前工具 live 投影行为。没有拷贝上游新模式管理框架。

## 决策

1. 两个添加入口共用保存/同步 hook；表单等待完成后关闭。失败保留输入，部分同步失败保留同一草稿 ID，复制失败也继续编辑同一副本。
2. 新建只加入三个工具的供应商列表，不自动激活；已有且正在使用的子供应商才投影到工具实际配置。保留子供应商元数据、排序、端点、故障队列和未受统一配置管理的参数；Codex TOML 逐字段合并。
3. 原生复用当前仓库的配置标准化、独立凭证分配、Codex 补偿事务、`sync_current_provider_for_app`。不能直接搬上游 `mode::current`，也不能用普通 `update` 替代投影：专项测试证明代理已停但仍有接管备份时，普通更新会覆盖代理地址；投影方法更新恢复备份并保留接管。
4. 旧统一 Codex 记录只有 `auth.OPENAI_API_KEY`。当前写入器有意保留官方 `auth.json`，因此同步旧记录前分配独立凭证引用并沿用原生凭证保存机制；已有引用保持稳定。首次创建的记录在显式启用时沿用现有旧格式迁移流程。
5. 各工具分别尝试同步，一个失败不阻断其他工具；返回失败工具名称，不回传可能带凭证的解析错误。部分成功也发既有刷新事件，避免列表缓存陈旧。
6. 取消勾选及删除均保护当前使用中的子记录；先切换后再重试，不擅自替用户切换配置。

## 替代方案与影响

- 只补按钮：改动最小，但保留保存不落工具配置、失败关闭和 Codex 认证问题，不满足本轮范围。
- 整套替换上游模块：可对齐更多模式，但需同时迁移编辑器、代理和工具状态依赖，风险及维护成本更高。
- 定向复用：改动限定三工具统一供应商；无新增持久 DTO 字段或数据库迁移。工具 API Key、兔子账户系统令牌及工具 OAuth 保持区分，不扩展到创作画布模型。
- 跨三个工具不是一个全局原子事务。成功项保留，失败项明确提示并可重试；Codex 沿用现有补偿事务。删除过程中遇到存储故障会保留父记录以便重试，但不承诺三工具一起回滚。
- 回退应用本轮局部 diff；已生成供应商继续使用原有数据结构。若未来提交，采用相应提交的 revert。无发布、无版本变更。
