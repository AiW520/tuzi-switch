# 供应商充值查询链接修复文档

## 问题描述

### 现象
- 系统中原有的预设供应商（如"兔子线路"、"codex订阅"、"gaccode"）显示正常，包含完整的"充值"和"查询"功能链接
- 用户通过系统功能添加新的供应商后，新供应商条目缺少"充值"和"查询"功能链接

### 影响范围
- 所有通过"添加供应商"功能新增的自定义供应商
- 不影响系统预设的供应商

## 问题根因

### 代码分析

问题位于 `src/components/providers/ProviderCard.tsx` 文件（第384-402行）：

```typescript
// 原有逻辑：只对特定预设供应商ID显示充值/查询链接
const codexLinks: Record<string, { recharge: string; query: string }> = {
  "tuzi-route": { recharge: "...", query: "..." },
  "coding": { recharge: "...", query: "..." },
  "gaccode": { recharge: "...", query: "..." },
};
// ... 其他预设链接

const links = linkMap[appId]?.[provider.id];
if (links) {
  // 只有匹配到预设ID的供应商才会显示充值/查询链接
}
```

### 根本原因
- 充值/查询链接的显示逻辑基于 `provider.id` 进行**硬编码匹配**
- 只有特定的预设供应商ID（如 `"tuzi-route"`、`"coding"`、`"gaccode"`）才会显示充值和查询链接
- 新添加的供应商ID不在这个硬编码列表中，因此不会显示充值和查询链接

## 修复方案

### 修改内容

**文件**: `src/components/providers/ProviderCard.tsx`（第384-463行）

1. **添加默认链接配置**：
```typescript
const defaultLinks = {
  recharge: "https://api.tu-zi.com/console/topup",
  query: "https://check.sydney-ai.com/",
};
```

2. **修改链接匹配逻辑**：当供应商不在预设列表中时使用默认链接
```typescript
const links = linkMap[appId]?.[provider.id] || defaultLinks;
```

3. **修改渲染逻辑**：所有供应商都显示充值和查询链接，同时根据条件显示 API Key 掩码或 API 地址

### 修复后的逻辑流程

```
供应商卡片渲染
    │
    ├─→ 获取链接配置
    │       ├─ 预设供应商 → 使用专属链接（如 coding、gaccode）
    │       └─ 自定义供应商 → 使用默认链接（兔子线路链接）
    │
    ├─→ 显示"充值"按钮（链接到充值页面）
    │
    ├─→ 显示"查询"按钮（链接到用量查询页面）
    │
    └─→ 显示附加信息
            ├─ 有 API Key → 显示掩码后的 Key
            └─ 无 API Key → 显示 API 地址
```

## 影响分析

### 正向影响

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 预设供应商（兔子线路等） | ✅ 显示充值/查询链接 | ✅ 保持不变 |
| 新增自定义供应商 | ❌ 不显示充值/查询链接 | ✅ 显示充值/查询链接 |
| API Key 显示 | ✅ 预设供应商显示掩码 | ✅ 保持不变 |
| API 地址显示 | ✅ 自定义供应商显示地址 | ✅ 保持不变 |

### 向后兼容性

- ✅ **完全向后兼容**：原有预设供应商的行为保持不变
- ✅ **无破坏性变更**：不会影响现有数据和配置
- ✅ **配置不变**：不需要修改任何配置文件

### 潜在风险

| 风险项 | 风险等级 | 说明 |
|--------|----------|------|
| 自定义供应商使用默认链接 | 低 | 默认链接指向兔子线路，对其他供应商可能不适用，但用户可自行选择是否使用 |
| UI 布局变化 | 低 | 所有供应商卡片现在都会显示充值/查询链接，布局稍有变化 |

## 验证方法

### 测试步骤

1. **启动应用**：运行 `pnpm tauri dev` 或直接运行构建后的可执行文件
2. **添加新供应商**：点击右上角 `+` 按钮添加一个自定义供应商
3. **验证显示**：新供应商卡片应显示"充值"和"查询"链接
4. **验证功能**：点击链接应正确打开对应页面

### 预期结果

- 新添加的供应商卡片显示"充值"和"查询"链接
- 链接与系统预设供应商使用相同的 URL
- API 地址或掩码 Key 正常显示

## 代码变更对比

### 修改前

```typescript
const links = linkMap[appId]?.[provider.id];
if (links) {
  // 显示充值/查询链接
}
// 否则显示 API 地址
```

### 修改后

```typescript
const defaultLinks = {
  recharge: "https://api.tu-zi.com/console/topup",
  query: "https://check.sydney-ai.com/",
};
const links = linkMap[appId]?.[provider.id] || defaultLinks;
// 始终显示充值/查询链接
// 根据条件显示 API Key 或地址
```

## 总结

### 修复效果

✅ **功能修复**：新添加的供应商现在会正确显示"充值"和"查询"功能链接
✅ **一致性保障**：新供应商的充值和查询链接与系统原有供应商使用相同的索引链接
✅ **无副作用**：不影响现有功能和数据

### 经验教训

1. **避免硬编码**：使用硬编码的 ID 列表限制功能显示会导致扩展性问题
2. **提供默认值**：当没有匹配项时应提供合理的默认行为
3. **保持一致性**：同类组件应保持一致的功能展示
