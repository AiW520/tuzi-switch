# 开发缓存重定向与安全清理方案

## 1. 结论

该能力可以实现，建议命名为 **开发缓存管家**，由两部分组成：

1. **缓存路由**：默认仅向兔子 Switch 启动的子进程注入缓存环境变量；Windows 可选开启“全局模式”，将受管变量写入当前用户环境，使之后启动的外部终端、IDE 与 Codex 使用指定缓存盘。
2. **安全清理**：只管理兔子 Switch 创建并登记过的缓存目录，按会话、时间、容量和磁盘水位清理。

全局模式只管理明确列入白名单的缓存环境变量，并在首次修改前备份原始注册表值；关闭时精确恢复。仍不直接搬迁或清空 ChatGPT、Codex、Claude 的整个用户目录，那些目录混有登录状态、配置、会话、数据库和凭据，不属于可随时删除的缓存。

## 2. 目标与边界

### 2.1 目标

- 用户可指定缓存根目录，例如 `D:\DevCache`。
- 从兔子 Switch 启动的终端和项目命令优先把可重建缓存写入该目录。
- 命令正常结束后，自动清理本次运行产生的临时文件。
- 异常退出产生的残留，可在下次启动或达到 TTL 后回收。
- 支持查看各类缓存大小、最后使用时间和预计可释放空间。
- 高并发扫描、清理时限制内存、CPU 和磁盘 I/O 占用。

### 2.2 明确不做

- 不自动删除用户项目源码、`node_modules`、Python 虚拟环境、Docker Volume、数据库、会话历史和登录凭据。
- 不把 `CODEX_HOME`、`CARGO_HOME`、`GRADLE_USER_HOME` 整体视为缓存并清空。
- 不直接移动 WSL 的 `ext4.vhdx` 或 Docker Desktop 磁盘镜像。
- 全局模式只能影响启用后新启动的进程；已经运行的终端、IDE、ChatGPT/Codex 必须完全退出并重启。

## 3. 推荐交互

在“设置 → 高级”增加“开发缓存”面板：

- 总开关：启用开发缓存管家。
- 缓存根目录：目录输入框、选择目录、恢复默认。
- 路由范围：
  - 会话临时文件；
  - Node.js；
  - Python；
  - Rust / Go；
  - JVM / .NET；
  - Docker / WSL 仅检测与引导。
- 清理策略：
  - 仅手动；
  - 启动兔子 Switch 时清理过期项；
  - 每次任务结束后清理会话临时文件；
  - 缓存超过指定容量时按最久未使用顺序回收。
- 保护期：默认 24 小时，避免误清刚结束或异常退出的任务。
- 操作：扫描、预览清理、立即清理、打开缓存目录。

首次选择目录时创建管理标记文件。后续所有删除操作必须确认目标位于该标记目录之下；若标记丢失，只允许扫描，不允许自动删除。

## 4. 目录布局

```text
<缓存根目录>/tuzi-switch-cache/
├─ .managed-cache.json
├─ sessions/
│  └─ <会话ID>/
│     ├─ temp/
│     ├─ lease.json
│     └─ heartbeat
├─ shared/
│  ├─ npm/
│  ├─ pnpm-store/
│  ├─ yarn/
│  ├─ pip/
│  ├─ uv/
│  ├─ go-build/
│  ├─ go-mod/
│  ├─ nuget/
│  └─ gradle/
└─ projects/
   └─ <规范路径哈希>/
      ├─ cargo-target/
      └─ python-pycache/
```

共享下载缓存与项目构建产物必须分开。Rust `target` 等构建目录按“规范化项目路径哈希”隔离，避免不同项目互相污染；目录名不直接包含项目路径，减少隐私泄露和非法字符问题。

## 5. 缓存分类与策略

| 等级 | 示例 | 默认策略 |
|---|---|---|
| A：会话临时文件 | `TEMP`、`TMP`、启动脚本、中间响应文件 | 任务结束后删除；异常残留按 TTL 回收 |
| B：可重建共享缓存 | npm、pnpm、Yarn、pip、uv、Go 下载/构建缓存、NuGet | 按容量和最后使用时间清理，优先调用工具原生命令 |
| C：项目构建缓存 | Cargo `target`、Python `pycache` | 按项目隔离；仅在无活跃租约时清理 |
| D：状态或用户数据 | `CODEX_HOME`、`CARGO_HOME` 凭据、虚拟环境、Maven 本地安装产物、Docker Volume | 永不自动删除，仅提示 |

首版建议支持：

| 生态 | 子进程路由方式 | 清理方式 |
|---|---|---|
| 通用临时目录 | `TEMP`、`TMP`；Unix 补充 `TMPDIR` | 直接清理兔子 Switch 会话目录 |
| npm | `npm_config_cache` | 调用 npm 原生命令或安全删除已登记目录 |
| pnpm | 子进程级 store-dir 配置 | 优先 `pnpm store prune` |
| Yarn | `YARN_CACHE_FOLDER`；Berry 项目缓存需识别并排除 | 仅清共享缓存，不碰项目 `.yarn/cache` |
| pip | `PIP_CACHE_DIR` | `pip cache purge/remove` |
| uv | `UV_CACHE_DIR` | `uv cache prune/clean` |
| Python 字节码 | `PYTHONPYCACHEPREFIX` | 清理项目哈希目录 |
| Cargo | `CARGO_TARGET_DIR` | 清理项目哈希目录；不改 `CARGO_HOME` |
| Go | `GOCACHE`、`GOMODCACHE` | `go clean` 对应缓存项 |
| Gradle | 可选独立缓存目录 | 先停止相关 daemon，再清过期缓存 |
| Maven | 可选 `maven.repo.local` | 默认仅统计；本地仓库可能含用户 `install` 产物 |
| NuGet | `NUGET_PACKAGES` | `dotnet nuget locals` |

Docker 和 WSL 在首版只显示空间占用、风险说明和官方操作入口，不由兔子 Switch 直接删除镜像、容器、Volume 或虚拟磁盘。

## 6. 与现有架构的接入点

当前项目已经有统一设置模型、终端偏好设置、Provider 终端启动和会话恢复终端启动链路，可在此基础上增加：

### 6.1 前端

- 新增 `DevelopmentCacheSettings` 设置组件。
- 在 `AppSettings` 增加 `developmentCache` 配置对象。
- 新增缓存扫描结果、清理预览和执行结果类型。
- 首版放在“高级设置”，避免挤占常用设置。

### 6.2 Rust 后端

建议新增独立模块，而不是继续扩充现有终端文件：

```text
src-tauri/src/dev_cache/
├─ mod.rs          # 对外接口
├─ config.rs       # 配置校验、路径规范化
├─ routing.rs      # 按生态生成子进程环境变量
├─ lease.rs        # 会话租约、心跳和异常恢复
├─ scanner.rs      # 流式扫描与统计
├─ cleaner.rs      # 白名单清理、限速与原生命令适配
└─ safety.rs       # 根目录、符号链接、重解析点与越界校验
```

接入现有两条启动路径：

1. Provider 终端启动：将缓存环境变量合并到现有 Provider 环境变量中。
2. 会话恢复/项目命令启动：在实际命令外包一层会话启动器，建立租约并在命令结束后回收 A 类临时目录。

当前终端启动后与兔子 Switch 解耦，不能仅依赖 Tauri 返回值判断任务结束。需要由启动脚本负责 `finally/trap` 清理，并配合租约与心跳处理强制关闭、断电等异常情况。

### 6.3 Tauri 命令

建议提供最小接口：

- `validate_dev_cache_root`
- `scan_dev_cache`
- `preview_dev_cache_cleanup`
- `clean_dev_cache`
- `open_dev_cache_directory`

扫描、预览、执行分离，用户能在删除前看到分类、数量、大小和跳过原因。

## 7. 清理安全设计

以下规则必须全部满足：

1. 缓存根目录不能是磁盘根目录、用户主目录、项目根目录、系统目录或兔子 Switch 配置目录。
2. 删除前规范化根目录和目标目录，确认目标严格位于管理根目录内部。
3. 只删除清单中登记的相对路径；禁止接受前端传入任意绝对删除路径。
4. 扫描时不跟随符号链接；Windows 下拒绝穿越 Junction、Mount Point 等重解析点。
5. 活跃租约目录禁止删除；无法判断时按“正在使用”处理。
6. 文件占用、权限不足或工具清理失败时跳过，不重试轰炸磁盘。
7. 首次清理和策略变更后首次清理必须预览确认。
8. 每次操作记录释放字节数、跳过项和错误摘要，不记录密钥、文件内容或完整敏感命令。

## 8. 性能设计

- 使用迭代式目录遍历，不把完整文件列表一次性载入内存。
- 统计按目录聚合，只保留有界 Top-N 大项。
- 删除并发默认 2，最大不超过 4；机械硬盘可自动降为 1。
- 大文件直接删除，不读取内容；日志与清单采用流式写入。
- 扫描和清理支持取消，前端关闭页面后不继续无边界占用资源。
- 同一缓存根目录使用进程级锁，避免多个兔子 Switch 实例同时清理。
- 设置磁盘软水位和硬水位时，仅回收 A/B/C 类，不突破 D 类保护边界。

## 9. 关键限制

### 9.1 ChatGPT / Codex 自身缓存

兔子 Switch 可以控制“经它启动的命令”的子进程环境，因此能够重定向这些命令使用的临时目录和工具缓存。

但 ChatGPT 桌面端、Codex 桌面端或其他 IDE 自己维护的 WebView/Electron 缓存、登录数据库和会话状态，不应由本功能猜测路径并自动清理。若以后要支持，应按具体客户端版本建立独立适配器，并默认只做检测与官方清理入口。

### 9.2 跨盘性能

pnpm、uv 等工具可能利用硬链接或 reflink。缓存与项目不在同一文件系统时，可能退化为复制，节省系统盘空间但增加安装耗时和磁盘写入。界面应明确提示该权衡。

## 10. 分阶段实施

### 第一阶段：Windows 安全 MVP（推荐）

- 设置缓存根目录和总开关。
- 先接入兔子 Switch 已有的 Provider 终端启动链路，不宣称管理外部自行启动的 ChatGPT/Codex/IDE 进程。
- 支持通用临时目录、npm/pnpm、pip/uv；共享缓存仅手动或按 TTL 清理。
- 会话租约、TTL 回收、扫描、预览、手动清理。
- 完整路径安全校验和有限并发。

### 第二阶段：通用启动抽象与全平台扩展

- 抽象 `TerminalLaunchSpec`，统一应用类型、命令、工作目录、Provider 环境变量和缓存环境变量。
- 扩展 Codex、Gemini、Claude 等实际命令启动，而不是继续依赖 Claude 专用启动脚本。
- 补齐 Windows、macOS、Linux 的会话恢复启动与包装脚本清理。
- 增加 Cargo、Go 等按项目路径哈希隔离的构建缓存。

### 第三阶段：策略化管理

- 容量上限、软/硬水位、LRU 清理。
- Yarn、Gradle、Maven、NuGet 适配。
- 按项目展示占用和一键清理。
- 工具不可用、跨盘性能、活跃任务状态提示。

### 第四阶段：外部工具引导

- Docker Desktop、WSL 空间检测。
- 生成可审阅的官方迁移/清理操作，不直接执行高风险删除。
- 评估特定 ChatGPT/Codex 客户端的只读缓存检测适配。

## 11. 验收标准

- 开启后，新启动任务的受支持缓存能落到指定根目录。
- 关闭后不再注入变量，不影响系统和其他终端。
- 两个项目并发构建互不覆盖，清理一个项目不影响另一个项目。
- 活跃任务、符号链接目标、管理根目录之外的文件均不会被删除。
- 异常关闭后，残留会话目录在保护期后可被识别和回收。
- 10 万级文件扫描内存保持有界，取消操作能及时停止。
- 清理前后释放空间可核对，失败项有明确原因。

## 12. 推荐决策

建议先实施第一阶段，并将产品承诺限定为：

> 管理兔子 Switch 启动的开发任务缓存，而不是清理电脑上一切缓存。

该边界能覆盖大部分“运行项目导致系统盘快速增长”的场景，同时避免误删账号状态、项目依赖、离线仓库和容器数据。
